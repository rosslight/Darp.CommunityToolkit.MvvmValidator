DataAnnotations validation for [CommunityToolkit.Mvvm](https://github.com/CommunityToolkit/dotnet) view models that works
with trimming and Native AOT. A source generator writes the validation code, so nothing is discovered with reflection
at runtime.

```shell
dotnet add package Darp.CommunityToolkit.MvvmValidator
```

Requirements:

- .NET 10
- View models and their containing types are `partial`. A code fix adds missing modifiers.
- Attributes that only target properties, like `[Compare]`, need `[property: ...]` on `[ObservableProperty]` fields.

## Usage

Derive from `ValidatingObservableObject` instead of `ObservableValidator` and make the class `partial`:

```csharp
using System.ComponentModel.DataAnnotations;
using CommunityToolkit.Mvvm.ComponentModel;
using Darp.MvvmValidator;

public partial class SignUpViewModel : ValidatingObservableObject
{
    public SignUpViewModel() => ValidateAllProperties();

    [ObservableProperty]
    [Required]
    [StringLength(20, MinimumLength = 3)]
    [Display(Name = "User name")]
    public partial string? UserName { get; set; }

    [ObservableProperty]
    [Required]
    public partial string? Password { get; set; }

    [ObservableProperty]
    [Compare(nameof(Password))]
    public partial string? ConfirmPassword { get; set; }

    [CustomValidation(typeof(SignUpViewModel), nameof(ValidateInvite))]
    public string? InviteCode
    {
        get;
        set => SetProperty(ref field, value);
    }

    public static ValidationResult? ValidateInvite(string? code, ValidationContext context) =>
        code is null or "WELCOME" ? ValidationResult.Success : new ValidationResult("Unknown invite code");
}
```

## Behavior

- Properties with validation attributes are validated whenever they change, before `PropertyChanged` reaches
  subscribers. `[NotifyDataErrorInfo]` and `SetProperty(..., validate: true)` are not needed.
- Results match `Validator.TryValidateProperty`, including `[CustomValidation]`, `[Compare]` and resource-based messages.
- When a `[Compare]` target changes, the comparing property is validated again, unless it is still untouched.
- `ValidateAllProperties` and `ClearErrors` work as in `ObservableValidator`. `SetErrors` adds results of
  asynchronous or server-side validation.

## Diagnostics

The package turns off the toolkit's MVVMTK0006, which only accepts `ObservableValidator`, and reports these instead:

| Id | Reported when |
| --- | --- |
| DMV0001 | A validated type or a containing type is not partial, or is file-local. A code fix adds `partial` |
| DMV0002 | A `[CustomValidation]` method is missing, not public static, or has the wrong signature |
| DMV0003 | An `[ObservableProperty]` member has validation attributes, but its type is no validating view model |
| DMV0004 | A `[Compare]` target is not a readable, accessible property |
| DMV0005 | An attribute or property cannot be expressed in generated code, e.g. a ref struct or `dynamic` property |

`[Compare]`, `[MinLength]`, `[MaxLength]` and `[Length]` make the trim analyzer and the trimmer warn where they are
applied. The package suppresses these warnings when the generated code avoids the reflection they warn about. For
properties with hand-written accessors or a field initializer, the warnings stay, because suppressing them would also
hide warnings in that code.

## Development

- Format with [CSharpier](https://csharpier.com): `dotnet tool restore`, then `dotnet csharpier format .`
- Runtime tests also run as a Native AOT executable in CI, which proves the generated code is trim safe.
- Generator tests snapshot the generated code with [Verify](https://github.com/VerifyTests/Verify).
- Releases come from [Conventional Commits](https://www.conventionalcommits.org) via
